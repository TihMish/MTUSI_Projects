# Product Brief: MeetingFlow

## Выбранный кейс
Бронирование переговорных / учебных комнат в кампусе «Школы 21».

## Название продукта (рабочее)
**MeetingFlow** — сервис для бронирования переговорных комнат.

## Цель и задача продукта
**Цель:** Упростить и ускорить процесс бронирования переговорных комнат для сотрудников и студентов кампуса.

**Задача:** Создать веб-приложение, которое позволяет пользователям:
- просматривать доступные комнаты,
- бронировать их на нужное время,
- отменять бронирования,
- получать подтверждение операции.

## Целевая аудитория

| Роль | Описание | Явные потребности | Скрытые потребности |
|------|----------|-------------------|---------------------|
| Студент / сотрудник | Пользователи, которым нужно забронировать комнату для встречи, учёбы или созвона | Быстро найти свободную комнату, забронировать её, получить подтверждение | Чувство уверенности, что бронирование действительно состоялось, и никто не займёт комнату без предупреждения |
| Администратор | Сотрудник, управляющий комнатами и бронированиями | Видеть все бронирования, управлять комнатами, разрешать конфликты | Контроль и прозрачность использования ресурсов кампуса |

## Основной пользовательский сценарий (успешный путь)

1. Пользователь открывает страницу сервиса.
2. Видит список всех переговорных комнат с указанием вместимости и оснащения.
3. Выбирает комнату.
4. Видит расписание слотов (свободные и занятые).
5. Выбирает свободный слот.
6. Вводит название встречи и количество участников.
7. Нажимает «Забронировать».
8. Получает подтверждение бронирования.

## Базовый промпт для генерации прототипа

**Цель:** Сгенерируй low-fi HTML-прототип веб-приложения для бронирования переговорных комнат.

**Ключевые экраны:**
1. **Главный экран** — список комнат с фильтрацией по вместимости, названию и оснащению.
2. **Экран комнаты** — информация о комнате (вместимость, оснащение, описание), расписание слотов на выбранную дату, свободные и занятые слоты.
3. **Экран бронирования** — форма с полями: название встречи, количество участников, дата, время начала, время окончания.
4. **Экран успеха** — сообщение об успешном бронировании с указанием даты, времени и комнаты.
5. **Экран ошибки** — сообщение о конфликте, если слот уже занят, с предложением выбрать другое время.

**Пользовательский сценарий:**
Пользователь выбирает комнату, смотрит её расписание, выбирает свободный слот, заполняет форму бронирования, получает подтверждение. Если слот занят — видит сообщение об ошибке и предложение выбрать другой слот.
