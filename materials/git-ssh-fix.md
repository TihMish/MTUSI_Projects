# Не проходит push: Permission denied (publickey)

Этот файл нужен, если терминал ответил тебе примерно так:

```
git@gitlab.example.ru: Permission denied (publickey).
fatal: Could not read from remote repository.
```

или так:

```
remote: HTTP Basic: Access denied
fatal: Authentication failed for 'https://gitlab.example.ru/...'
```

Это самая частая ошибка первого дня. Она случается почти у всех и не имеет отношения к тому, насколько ты разобрался в задании. Разбирается за десять минут.

---

## Что вообще произошло

GitLab не пускает кого попало писать в репозиторий. Он должен убедиться, что это ты. Есть два способа это доказать.

**По HTTPS** — логином и паролем. Ссылка начинается с `https://`. В нашей установке этот способ для записи отключён, поэтому клонировать по HTTPS получится, а отправить изменения — нет.

**По SSH** — парой ключей. Ссылка начинается с `git@`. Ты создаёшь на своей машине два файла: приватный ключ (остаётся у тебя, никому не показываешь) и публичный (кладёшь в GitLab). Дальше они узнают друг друга сами, без пароля.

Ошибка `Permission denied (publickey)` означает одно из двух: ключей у тебя нет, либо публичный ключ не добавлен в GitLab.

---

## Шаг 0. Проверь, может ключ уже есть

```bash
ls -al ~/.ssh
```

Если в списке есть `id_ed25519` и `id_ed25519.pub` — ключ есть, переходи к шагу 2.
Если папки нет вообще или в ней пусто — переходи к шагу 1.

---

## Шаг 1. Создай ключ

**macOS и Linux** — в терминале.
**Windows** — в Git Bash (он ставится вместе с Git; найди его в меню «Пуск»).

```bash
ssh-keygen -t ed25519 -C "твоя.почта@example.com"
```

Дальше терминал задаст три вопроса:

1. **Где сохранить файл** — просто нажми Enter, путь по умолчанию подходит.
2. **Passphrase** — можно оставить пустым, нажми Enter.
3. **Повтори passphrase** — снова Enter.

В конце появится картинка из символов — это нормально, ключ создан.

> Если поставишь passphrase, его придётся вводить при каждом push. На бассейне это лишнее — оставь пустым.

---

## Шаг 2. Добавь публичный ключ в GitLab

Сначала выведи содержимое **публичного** ключа. Обрати внимание на `.pub` в конце — это важно.

```bash
cat ~/.ssh/id_ed25519.pub
```

Появится одна длинная строка вида `ssh-ed25519 AAAAC3Nza... твоя.почта@example.com`. Скопируй её целиком, от `ssh-ed25519` до конца.

> **Частая ошибка:** скопировать `id_ed25519` вместо `id_ed25519.pub`. Первый — приватный, его никуда выкладывать нельзя, и GitLab его всё равно не примет.

Можно скопировать сразу в буфер обмена:

```bash
# macOS
pbcopy < ~/.ssh/id_ed25519.pub

# Windows (Git Bash)
clip < ~/.ssh/id_ed25519.pub

# Linux
xclip -selection clipboard < ~/.ssh/id_ed25519.pub
```

Теперь в GitLab:

1. Нажми на свой аватар в правом верхнем углу → **Preferences** (или **Edit profile**).
2. В левом меню выбери **SSH Keys**.
3. Нажми **Add new key**.
4. Вставь скопированную строку в поле **Key**.
5. Поле **Title** заполнится само. Поле **Expiration date** можно очистить.
6. Нажми **Add key**.

---

## Шаг 3. Проверь, что связь работает

```bash
ssh -T git@<адрес_твоего_gitlab>
```

Адрес возьми из ссылки на клонирование — это то, что идёт после `git@` и до двоеточия.

При первом подключении появится вопрос:

```
The authenticity of host '...' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Напиши `yes` и нажми Enter. Это нормальный вопрос, он задаётся один раз.

Если всё получилось, ответ будет такой:

```
Welcome to GitLab, @твой_логин!
```

Всё, можно работать.

---

## Шаг 4. Если репозиторий уже склонирован по HTTPS

Заново клонировать не нужно. Посмотри, какой адрес прописан:

```bash
git remote -v
```

Если там `https://...` — переключи на SSH:

```bash
git remote set-url origin git@<адрес_gitlab>:<группа>/<репозиторий>.git
```

Точную SSH-ссылку возьми на странице проекта: кнопка **Clone** → блок **Clone with SSH**.

Проверь, что подменилось:

```bash
git remote -v
```

Оба адреса должны начинаться с `git@`. Теперь пробуй:

```bash
git push origin develop
```

## Другие ошибки в этом же месте

**`Could not open a connection to your authentication agent`**

Агент не запущен. Запусти и добавь ключ:

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

**`Host key verification failed`**

Ты ответил `no` на вопрос из шага 3 или закрыл терминал. Повтори `ssh -T` и ответь `yes`.

**`remote: The project you were looking for could not be found`**

Ключ в порядке, а вот адрес репозитория — нет. Скорее всего опечатка в ссылке или ты пытаешься писать в чужой проект. Сверь адрес с кнопкой **Clone** на странице своего проекта.

**`git: command not found`**

Git не установлен. На бассейне он должен быть на станции — позови дежурного, это не твоя задача.

**`error: src refspec develop does not match any`**

Ветки `develop` нет — ты её не создал или находишься в другой. Проверь:

```bash
git branch
```

Звёздочка стоит напротив текущей ветки. Если `develop` в списке нет:

```bash
git checkout -b develop
```

**push проходит, но в GitLab пусто**

Ты смотришь не на ту ветку. В веб-интерфейсе над списком файлов есть переключатель веток — переключись на `develop`.

---

## Если ничего не помогло

Не сиди над этим больше пятнадцати минут — это техника, а не задание. Иди к дежурному и покажи три вещи:

1. Вывод `ls -al ~/.ssh`
2. Вывод `ssh -T git@<адрес_gitlab>`
3. Вывод `git remote -v`

С этими тремя строчками проблема чинится за минуту.
