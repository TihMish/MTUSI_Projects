# Нормативный протокол v4.0

Все примеры и проверяющий относятся к этой версии. Python — стандартная
библиотека; на станциях фиксируется одна версия Python 3.10 или новее.
Никакая программа участника не получает имя профиля или его эталонный уровень.
Алгоритм проверяющего открыт; безопасность изоляции исходного кода не обещается.

## 1. Файлы и право изменения

`datasets/bank_reference.txt`, `answers_reference.txt`: эталонные 50 вопросов.
`datasets/bank_review.txt`, `answers_review.txt`: проверяемые 50 вопросов.
`datasets/bank_team.txt`, `answers_team.txt`: создаваемые командой 20 вопросов.
Все фрагменты — в `datasets/snippets/<id>.py` и `<id>.out`.

Эталонные ID 101–150; проверяемые 201–250; свои ID от 1000.
В reference запрещены изменения и удаления. В review разрешено только полное
удаление дефектного вопроса и связанных записей/файлов; исправлять или
переформулировать исходные вопросы нельзя. В team разрешена разработка до сдачи.
Файлы команды выданы пустыми заготовками: в них только строки-комментарии. Для реальной выдачи
обе исходные группы присутствуют; маленькие проверочные банки могут иметь
другие положительные ID и размеры. Загрузчик не зашивает число 50 или 100.

Запрещено изменять `src/partner/`, включая манифест и линтер. Приёмщик сверяет
эту папку с копией выдачи; локальная проверка не защищает сама себя от переписывания.

## 2. Текстовый формат

UTF-8, LF. Пустые строки и строки с первым непробельным # игнорируются.
Одна запись — строка. Разделитель полей — вертикальная черта. Пробелы по краям
полей удаляются. Вертикальная черта внутри значения запрещена; используйте
словесное обозначение разделителя в вопросах. Значения не могут быть пустыми,
кроме уровня вне шкалы. Вопросы содержат ровно шесть полей:

```text
id | тема | уровень | тип | в_шкале | текст
```

ID — положительное целое. Темы: ввод, данные, ошибки, структура.
Типы: one, many, short, output. В шкале: 1 с уровнем 1–5 или 0 с пустым уровнем.

Ответы содержат ровно четыре поля:

```text
id | метка | верный | текст
```

Верный — 0 или 1. Для one/many метки — А, Б, В, Г, Д (кириллица), не повторяются
в одном вопросе. Вариантов 2–5. В one ровно один верный; в many от двух до всех.
Для short метка -, все записи помечены 1; перечислены принимаемые формы ответа.
Для output строк ответов нет: код и ожидаемый вывод находятся в файлах фрагментов.

Вывод output содержит ровно одну непустую строку; завершающий LF допустим.
Многострочный и пустой эталон для обязательного проекта недопустимы.
Программа теста читает `.py` как текст, не исполняет предъявляемые фрагменты.

## 3. Битость и счётчики

Вопрос битый при нарушении любого ограничения выше: ID/число полей/допустимые
значения/непустой текст, неправильное количество правильных вариантов,
неправильные метки/строки ответов, отсутствие нужных ответов или фрагментов.
Связанные строки ответов должны лежать в группе того же вопроса.
Если ID повторяется, битые ВСЕ записи вопросов с этим ID.
Несколько дефектов одной строки вопроса дают ровно одну битую запись.

Запись с непарсируемым ID всё равно входит в всего и битых. Пустые строки и
комментарии не входят. Осиротевшая строка ответов не создаёт вопрос для --scan,
но является ошибкой целостности на финальном --bank-check.
Содержательный брак программно не распознаётся: его нельзя смешивать со счётчиком битых.

--scan печатает строго следующие строки в этом порядке, везде разделитель ` | `:

```text
всего | N
битых | B
вне шкалы | O
уровень 1 | L1
уровень 2 | L2
уровень 3 | L3
уровень 4 | L4
уровень 5 | L5
тема ввод | T1
тема данные | T2
тема ошибки | T3
тема структура | T4
тип one | K1
тип many | K2
тип short | K3
тип output | K4
```

Здесь буквы заменяются неотрицательными целыми. Все разрезы считают только
структурно исправные вопросы. N = B + сумма типов = B + сумма тем;
сумма уровней + O = N − B. В конце ровно LF, без пустой строки.

## 4. Интерфейсы для независимых проверок

Обязательны две функции в `src/bank.py`:

```python
load(folder)  # -> {"questions": [...], "total": int, "broken": int}
check(question, answer)  # -> "верно" / "неверно" / "не принят"
```

Дополнительные ключи результата load разрешены. questions — список только
структурно исправных вопросов. Каждая запись — словарь:

```python
{"id": 11, "topic": "ввод", "level": 1, "type": "one", "scale": 1,
 "text": "Выберите два.",
 "options": [{"label": "А", "correct": True, "text": "2"},
             {"label": "Б", "correct": False, "text": "3"}],
 "code": "", "expected": ""}
```

У output options пуст, code и expected содержат тексты файлов.
У short options содержит принимаемые формы с label=- и correct=True.
У вне-шкального вопроса level=None. Модули bank.py и engine.py не печатают.
Порядок options соответствует файлу.

Для движка обязательны две функции в `src/engine.py`:

```python
start()  # -> новый словарь состояния знаний
observe(state, question, result)  # изменяет state на месте, возвращает None
```

Состояние знаний — JSON-совместимый словарь: числа без NaN/Infinity, строки,
bool, None, списки и вложенные словари со строковыми ключами. Оно содержит
только сведения для оценки знаний: гипотезы, счётчики принятых свидетельств,
противоречия и подобные данные вашей политики. В start создаётся независимый
новый словарь для каждой сессии. Принятый ответ в шкале обновляется по вашей политике.

Если result="не принят" или question["scale"]=0, observe возвращает None и
оставляет весь словарь state без изменений, в том числе после предыдущих
принятых ответов. Это проверяемый инвариант, а не готовая формула оценки.
Бюджет, показанные ID, генератор random и журнал всех попыток хранятся отдельно
от состояния знаний. Остальные функции выбора и вердикта группа определяет сама.
Решение не импортирует функции реализации из partner: load и check реализуются командой.

## 5. Проверка ответа

answer — строка без завершающего LF, либо None при EOF. None, пустая и состоящая
из пробелов строка дают не принят для любого типа.
one: обрезать края, привести метку к верхнему регистру; нужен один токен из меток.
many: метки через произвольные пробелы, регистр верхний, порядок и повторы несущественны.
Неизвестная метка или несколько токенов у one — не принят.
many верен только при точном равенстве множеству правильных меток; частичный — неверен.
short: strip + lower, затем сравнить со всеми принимаемыми формами.
output: strip ответа и эталона, далее точное сравнение; внутренние пробелы значимы.
Непустое неправильное слово у short/output — неверно, а не не принят.

Не принят не является свидетельством за или против уровня. Повторного ввода
нет: показанный вопрос расходует бюджет и больше не показывается.
Вне-шкальные вопросы можно вообще не задавать. Если заданы, они расходуют
бюджет, но не обновляют свидетельства об уровне и вычисляемую по ним уверенность.

## 6. Запуск и потоки

```sh
python3 src/main.py ПАПКА [--scan] [--seed ЦЕЛОЕ] [--explain]
```

Запуск из корня репозитория. --scan несовместим с --seed и --explain.
Ошибки аргументов/отсутствие папки или основного файла дают понятное сообщение
в stderr и ненулевой код. Битая запись внутри доступного банка не является
ошибкой запуска. При штатной сессии, включая EOF, код завершения 0.

Содержимое вопроса выводится в строго заданном порядке, каждая строка с
префиксом > и одним пробелом. Сначала текст вопроса. Для one/many затем варианты
в порядке файла, каждый как «метка) текст». Для output затем все строки исходного
кода, включая пустые, с сохранением отступов после префикса. Для short вариантов нет.
Дополнительных заголовков и пустых строк вне этого формата не печатайте.
Пример:

```text
> Выберите число два.
> А) 2
> Б) 3
ОТВЕТ:
```

Строка кода ОТВЕТ: показывается как > ОТВЕТ: и не является маркером ввода.
Текст записи/варианта не разбивается программой на дополнительные строки;
визуальный перенос терминалом допустим. Последняя строка блока — без префикса:

```text
ОТВЕТ:
```

После неё читается одна строка stdin. Печатайте этот маркер с flush=True.
Одна и та же версия кода, банка и Python, seed и последовательность ответов
должны давать одинаковые stdout и stderr. Сам по себе seed разных людей не уравнивает.

## 7. Лог и вердикт

Лог в stderr, каждый вызов печати с flush=True. Перед вопросом:

```text
1 | вопрос 11 | уровень 1 | тема ввод | тип one | в_шкале 1
```

После ответа:

```text
1 | ответ "А" | верно | дальше уровень 2
```

Поле ответа — JSON-строка: `json.dumps(answer, ensure_ascii=False)`.
Это однозначно экранирует кавычки и управляющие символы. При EOF — JSON null.
Для пустого ответа — "". Следующее решение — `уровень 1`…`уровень 5`,
`уровень -` для вне-шкального следующего вопроса или `стоп`.
Это целевой уровень; если его вопросы кончились, фактический уровень следующего
вопроса может отличаться по описанной политике замены. У вопроса вне шкалы в логе уровень -.

В конце ровно одна строка остановки, причина одна из четырёх:

```text
стоп | причина конец ввода
```

Причины и приоритет: конец ввода → сошлось → бюджет → вопросов нет.
Бюджет — показано 20 вопросов и политика ещё не сошлась. Пустой доступный банк
до первого вопроса даёт вопросов нет. Даже при EOF после показа вопрос считается
заданным и получает строку ответа null со статусом не принят и дальше стоп.

Последняя строка stdout — ровно один вердикт:

```text
УРОВЕНЬ 3 | ВОПРОСОВ 3 | УВЕРЕННОСТЬ 1.00
НЕ ОПРЕДЕЛЁН | ВОПРОСОВ 1 | УВЕРЕННОСТЬ 0.00
```

Количество — 0–20, уверенность — 0.00–1.00, ровно два знака, десятичная точка.
После вердикта нет пустых строк stdout. Если не получено ни одного принятого
ответа на вопрос в шкале: НЕ ОПРЕДЕЛЁН и 0.00. Уверенность — описанная эвристика,
а не автоматически подтверждённая вероятность. --explain обязателен: после вердикта
он дописывает в stderr строки с префиксом ОБЪЯСНЕНИЕ:, не меняя stdout ни на
символ. Без флага таких строк нет. Этап 3 проверяет оба запуска автоматически.

## 8. Автоматическая приёмка

См. `testing_rus.md`. --run проверяет четыре этапа; --bank-check запускается
отдельно. КОД ПРИНЯТ относится только к коду; содержание и участие проверяет пир.
--control КЛЮЧ повторяет те же правила на новых начальных числах. Новых скрытых критериев нет.
Проверяющий использует временные каталоги и удаляет их после проверки.
Исходный рабочий банк он не изменяет. Политика читает банк один раз за сессию.
