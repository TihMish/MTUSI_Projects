# Глоссарий проекта

Термины используются в README, протоколе, методичках и чек-листе в одном смысле.

| Термин | Значение в проекте |
|---|---|
| Адаптивность | Зависимость следующей сложности или остановки от предыдущих ответов |
| Группа | От одного до четырёх участников с одним проектом и одной общей приёмкой |
| Банк | Вопросы, связанные варианты/принимаемые ответы и фрагменты кода |
| Эталонная группа | 50 явно обозначенных исходных вопросов, корректность которых гарантирует выдача |
| Проверяемая группа | 50 вопросов для ревизии, среди которых не более десяти дефектных |
| Вопрос команды | Один из двадцати вопросов, созданных участниками |
| Дефект | Общее название структурной битости и содержательного брака |
| Битость | Нарушение машинно проверяемого формата или связи данных |
| Брак | Ошибка смысла/уровня/качества варианта при формально допустимой структуре |
| Ревизия | Проверка вопросов, обоснованное удаление дефектных, сохранение корректных |
| Эталонный ответ | Принимаемая форма или помеченный правильный вариант |
| ID | Уникальный положительный номер вопроса; это ключ, а не индекс списка |
| Связь по ключу | Соединение вопроса, ответов и фрагментов по одинаковому ID |
| Осиротевшая запись | Ответ, у которого больше нет вопроса |
| Целостность | Соблюдение ограничений и наличие требуемых связанных данных |
| Манифест | Контрольный список исходных ID и отпечатков данных для проверки сохранности |
| Хеш, SHA-256 | Отпечаток содержимого; изменение байтов меняет ожидаемый отпечаток |
| Тип вопроса | one, many, short или output; задаёт представление и сравнение ответа |
| one | Выбор ровно одного варианта |
| many | Выбор множества вариантов; в базе засчитывается только полное совпадение |
| short | Короткая строка, сравниваемая с перечнем допустимых форм |
| output | Ответ о выводе показанного кода; в проекте вывод однострочный |
| Тема | Предмет вопроса: ввод, данные, ошибки или структура |
| Уровень вопроса | Действие в голове: узнать, применить, собрать, проследить, найти контрпример |
| Уровень человека | Учебный вердикт теста по шкале 1–5; не экзаменационная оценка |
| Вне шкалы | Вопрос не даёт свидетельств об уровне, но расходует ход |
| Сессия | Один запуск диалога от первого вопроса до вердикта |
| История | Уже заданные вопросы и результаты ответов в текущей сессии |
| Политика | Правила старта, выбора, обновления состояния, остановки и вердикта |
| Состояние знаний | JSON-совместимый словарь для оценки знаний; бюджет и показанные ID хранятся отдельно |
| Свидетельство | Принятый верный или неверный ответ на вопрос в шкале |
| Не принят | Некорректный формат/пустой ответ; не свидетельство о знании |
| Уверенность | Описанная командой мера определённости; сама по себе не доказанная вероятность |
| Не определён | Допустимый отказ назвать уровень при недостатке свидетельств |
| Бюджет | Не более двадцати предъявленных вопросов за сессию |
| Холодный старт | Начало без сведений о человеке |
| Исчерпанный уровень | На нужной сложности не осталось подходящих незаданных вопросов |
| Противоречие | Наблюдения плохо согласуются с выбранной моделью знаний |
| Угадывание | Верный ответ без достаточного знания, моделируемый вероятностью попадания |
| Шум | Случайные или систематические отклонения от идеальной модели ответа |
| Идеальный профиль | Собеседник уровня L, всегда верный на вопросах ≤L и неверный выше |
| Симулятор | Программа, отвечающая вместо человека по заданной модели |
| Контрольный ключ | Число, которое проверяющий получает на приёмке; из него считаются начальные числа трёх прогонов |
| Начальное число (seed) | Число, с которого стартует генератор случайных чисел: при одинаковом числе и одинаковых данных программа повторяет свой выбор |
| Воспроизводимость | Совпадение результата при одинаковых коде, данных, окружении, вводе и seed |
| Ревизия | Проверка всех пятидесяти вопросов review и удаление доказанно дефектных |
| Гипотеза | Предсказание того, как изменение повлияет на наблюдаемые показатели |
| Точность на идеалах | Доля правильных вердиктов в 15 идеальных сессиях |
| Средняя длина | Сумма числа вопросов в сессиях, делённая на число сессий |
| Ложное завышение | Вердикт выше эталонного уровня там, где эталон определён |
| Ложное занижение | Вердикт ниже эталонного уровня там, где эталон определён |
| Протокол | Точный договор о файлах, функциях, вводе и выводе |
| CLI | Запуск программы с аргументами в терминале |
| Аргумент | Значение при вызове функции или программы |
| Флаг | Именованный параметр командной строки, например --scan |
| stdin | Стандартный поток ввода |
| stdout | Стандартный поток вывода: вопросы и вердикт |
| stderr | Отдельный поток: лог и сообщения об ошибках |
| EOF | Конец ввода; Python input() сообщает о нём исключением EOFError |
| Буфер | Промежуточное хранилище вывода, из-за которого текст может дойти позже |
| flush | Принудительная отправка накопленного вывода собеседнику |
| Код завершения | Целое число результата процесса; штатный результат проекта — 0 |
| Таймаут | Предельное ожидание; проверяющий завершает зависший подпроцесс |
| Подпроцесс | Отдельная программа, запущенная проверяющим |
| JSON-строка | Однозначная запись текста с экранированием; используется в поле ответа лога |
| Экранирование | Запись специальных символов так, чтобы их не путали с форматом |
| Модуль | Python-файл с функциями и данными |
| Точка входа | main.py: аргументы, координация, ввод и печать |
| Интерфейс | Договор об имени функции, аргументах, результате и ошибках |
| Чистая функция | В контексте методички — вычисляет результат без самостоятельной печати/ввода |
| Линтер | Проверка синтаксиса и отдельных правил оформления, не математической правильности |
| Commit | Снимок изменений в Git с идентификатором |
| Ветка | Линия разработки, которую можно слить с другой |
| Merge | Объединение веток |
| Конфликт | Место, где Git требует выбрать согласованное содержимое |
| Бронирование слота | Выбор другой командой открытого времени проверяющего; в этот момент ему открывается чек-лист |
| Freeze | Отправка, после которой сдаваемый commit больше не меняют |
| Формальный проверяющий | Один пир, который проводит единственную групповую приёмку и заполняет общий результат |
| Представитель группы | Участник, представляющий общий проект на единственной приёмке; другие могут дополнять |
| Технический эталон | Авторская реализация для проверки комплекта; не часть выдачи участникам |
| Пилот | Пробное выполнение полного проекта людьми целевого уровня с замером времени |

Битость и брак различаются способом обнаружения, а не важностью. Корректный
синтаксис не доказывает правильность смысла. Новый seed не меняет критерии зачёта.
