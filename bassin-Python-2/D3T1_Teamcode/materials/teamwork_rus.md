# Работа группы 

Один репозиторий, ветка `develop`, понятные небольшие коммиты. Число коммитов не
является мерой знаний. В `src/team.md` запишите состав, зоны ответственности,
ветки и 2 момента сквозной сборки первого дня.

| Зона ответственности | За что отвечает |
|---|---|
| Хранитель банка | `bank.load` и `bank.check`, связи данных, перепись, целостность |
| Дознаватель | Состояние знаний, `engine.start` и `engine.observe`, политика выбора |
| Методист | Ревизия всех 50 вопросов review и согласованность своих двадцати |
| Интегратор | CLI, диалог, лог, сборка, воспроизводимые запуски |

4 зоны распределяются между любым разрешённым числом людей. Вдвоём удобно
объединить банк с методикой, а движок — с интеграцией. Втроём методическую работу
совмещают с одной технической зоной. Один участник закрывает все четыре.

## Договор об интерфейсах

4 функции заданы протоколом жёстко: `bank.load`, `bank.check`,
`engine.start`, `engine.observe`. Для всех остальных запишите в `team.md`
имя, аргументы и результат **до** того, как разойдётесь писать код.

Банк не зависит от движка. Состояние знаний не смешивается с бюджетом и списком
показанных ID. Точка входа печатает; модули возвращают.

## Ревизия и свои вопросы

Ревизию распределите по непересекающимся диапазонам ID и вместе охватите все
пятьдесят. Решение по каждому ID заносится в общий `src/bank_review.md`.

Свои вопросы: 20 при одном участнике, по 10 при двух, 7, 7 и 6 при трёх. Диапазон ID 1000–1019 разделите заранее, чтобы не столкнуться на слиянии.
Перепроверьте вопросы друг у друга по рубрике: автор редко видит подсказку в
собственной формулировке. Если вы один — перечитайте свои после паузы на другую задачу.

## Сборки

Две сквозные сборки первого дня: промежуточная и перед живым показом. Для каждой
проверяйте одно и то же: загрузка → один учебный собеседник → EOF → отсутствие
повторов. Не откладывайте соединение модулей на второй день. Пока сессия не идёт
целиком, можно собирать на малом банке из `examples/`.
