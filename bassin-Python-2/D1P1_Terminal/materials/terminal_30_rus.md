# Справочник терминала первого дня

Терминал выполняет команды буквально: он не угадывает, где лежит файл, что ты хотел удалить и какой результат считаешь правильным.

Этот справочник — набор инструментов, а не готовые последовательности для заданий. Читай сообщение терминала, проверяй предположение небольшой командой и только потом меняй файлы. Если незнакомо слово, загляни в [`glossary_rus.md`](glossary_rus.md).

| Ситуация | Где смотреть |
| --- | --- |
| Неясно, где ты находишься и какой путь указать | [1. Папки и пути](#1-папки-и-пути) |
| Нужно исследовать файл, не изменяя его | [2. Просмотр данных](#2-просмотр-данных) |
| Нужно понять, завершилась ли программа успешно | [3. Запуск и результат](#3-запуск-и-результат) |
| Нужно подать ввод из файла или сохранить вывод | [4. Потоки и перенаправление](#4-потоки-и-перенаправление) |
| Нужно изменить набор файлов | [5. Файлы и папки](#5-файлы-и-папки) |
| Файлов много, а их имена похожи | [6. Маски имён](#6-маски-имён) |
| Файл существует, но не запускается | [7. Права](#7-права) |
| Нужно изменить текстовый файл | [8. Редактор](#8-редактор) |

## 1. Папки и пути

| Команда | Что можно узнать или сделать |
| --- | --- |
| `pwd` | Показать текущую папку |
| `ls` | Показать её содержимое |
| `ls -l` | Показать содержимое с правами, размерами и датами |
| `ls -a` | Показать также имена, начинающиеся с точки |
| `cd путь` | Перейти в другую папку |
| `clear` | Очистить экран, не удаляя файлы и историю команд |

Путь без `/` в начале отсчитывается от текущей папки. Например, `notes/day.txt` означает файл `day.txt` в папке `notes` относительно результата `pwd`.

Путь с `/` в начале отсчитывается от корня файловой системы. `..` означает родительскую папку, а `.` — текущую. Команда `ls путь` позволяет осмотреть другую папку, не переходя в неё.

Если терминал сообщает, что файл не найден, сначала сопоставь три вещи: результат `pwd`, имя из команды и результат `ls`.

## 2. Просмотр данных

| Команда | Что делает |
| --- | --- |
| `cat файл` | Печатает файл целиком |
| `cat -A файл` | Показывает также некоторые невидимые символы: конец строки как `$`, табуляцию как `^I` |
| `head -n 5 файл` | Печатает первые пять строк |
| `tail -n 5 файл` | Печатает последние пять строк |
| `wc -l файл` | Считает строки |
| `grep текст файл` | Печатает строки, где встречается указанный текст |
| `file файл` | Пытается определить тип содержимого файла |

Число после `-n` можно менять. Текст для `grep`, содержащий пробелы, заключай в кавычки: `grep "важная строка" notes.txt`.

Одна команда редко отвечает на все вопросы. Имена, размеры, количество строк, начало, конец и невидимые символы дают разные наблюдения. Сначала реши, какое свойство тебе нужно проверить.

## 3. Запуск и результат

| Команда | Что делает |
| --- | --- |
| `python3 файл.py` | Запускает программу Python |
| `bash файл.sh` | Выполняет команды из shell-скрипта |
| `echo $?` | Показывает код возврата последней завершившейся команды |
| `history` | Показывает ранее введённые команды |

Аргументы пишутся после имени программы: `python3 tool.py один два`. Это не то же самое, что данные, которые программа читает из стандартного ввода.

У завершившейся команды есть код возврата. Обычно `0` означает успешное завершение, другое число — ошибку. Но код не заменяет проверку вывода: команда может завершиться без аварии и всё равно выдать неверный результат.

`echo $?` относится только к команде непосредственно перед ним. Если между запуском программы и `echo $?` выполнить что-то ещё, ты увидишь уже новый код.

У программы могут быть три разных канала:

- стандартный ввод — данные, которые она получает;
- стандартный вывод — обычный результат;
- стандартный поток ошибок — диагностические сообщения.

## 4. Потоки и перенаправление

| Форма команды | Что происходит |
| --- | --- |
| `команда < вход.txt` | Стандартный ввод берётся из файла |
| `команда > результат.txt` | Стандартный вывод записывается в файл; прежнее содержимое стирается |
| `команда >> журнал.txt` | Стандартный вывод дописывается в конец файла |
| `команда 2> ошибки.txt` | Стандартный поток ошибок записывается отдельно |

Перенаправления можно сочетать с командами запуска, но сначала определи, откуда программа должна получить данные и куда должен попасть каждый результат.

Символ `>` опаснее, чем выглядит: существующий файл будет перезаписан без вопроса. Перед запуском проверь имя справа от него.

Команды `echo "текст" > файл` и `echo "текст" >> файл` используют те же правила: первая начинает файл заново, вторая дописывает строку.

## 5. Файлы и папки

| Команда | Что делает |
| --- | --- |
| `mkdir путь` | Создаёт папку; вариант `mkdir -p a/b/c` создаёт недостающую цепочку |
| `touch файл` | Создаёт пустой файл или обновляет время существующего |
| `cp откуда куда` | Копирует файл |
| `mv откуда куда` | Перемещает или переименовывает |
| `rm файл` | Удаляет файл |
| `rm -r папка` | Удаляет папку вместе с содержимым |

`rm` не отправляет файлы в корзину и обычно не позволяет отменить действие. До удаления ответь себе на два вопроса: какой путь сейчас получился и какие именно имена ему соответствуют.

## 6. Маски имён

Маска описывает похожие **имена**. Терминал подставляет подходящие имена ещё до запуска команды; содержимое файлов маска не анализирует.

| Маска | Что означает | Нейтральный пример совпадения |
| --- | --- | --- |
| `*` | Любое количество любых символов, в том числе ни одного | `*.tmp` → `old.tmp` |
| `?` | Ровно один любой символ | `page?.txt` → `page7.txt` |
| `cache-*` | Имя начинается с `cache-` | `cache-2026` |
| `report??.txt` | После `report` идут ровно два символа | `report01.txt` |

Один и тот же шаблон можно сначала передать безопасной команде просмотра, например `ls logs/*.tmp`, и лишь после проверки — команде, которая меняет файлы. Не считай маску правильной только потому, что она короткая: проверь и то, что она выбрала, и то, что оставила.

Если имена похожи недостаточно, посмотри на другие наблюдаемые свойства файлов. Справочник намеренно не решает за тебя, какое свойство важно.

## 7. Права

| Команда | Что делает |
| --- | --- |
| `chmod +x файл` | Добавляет право на выполнение |
| `chmod -x файл` | Убирает право на выполнение |

Первая колонка `ls -l` выглядит примерно как `-rwxr--r--`. Буквы означают: `r` — чтение, `w` — изменение, `x` — выполнение.

Отсутствие `x` мешает запуску через `./файл`, но интерпретатор можно вызвать явно: `python3 файл.py` или `bash файл.sh`.

## 8. Редактор

Команда `nano файл` открывает текстовый редактор в терминале.

| Клавиши | Что делают |
| --- | --- |
| Стрелки | Перемещают курсор |
| Ctrl+O, затем Enter | Сохраняют файл |
| Ctrl+X | Закрывают редактор |
| Ctrl+K | Вырезают строку |
| Ctrl+W | Ищут текст |

В подсказках `nano` символ `^` означает Ctrl.

Если случайно открылся `vim`, выйти без сохранения можно так: Esc, затем `:q!`, затем Enter.

## 9. Когда терминал отвечает неожиданно

| Ответ или поведение | Что это может означать | Что проверить |
| --- | --- | --- |
| `command not found` | Опечатка или команда недоступна | Написание команды |
| `No such file or directory` | Указанного пути нет относительно текущей папки | `pwd`, затем `ls` нужного уровня |
| `Permission denied` | Не хватает прав на действие | `ls -l`, способ запуска и необходимость `chmod` |
| `Is a directory` | Команда ожидала файл, но получила папку | Последнюю часть пути |
| `Directory not empty` | Выбрано действие только для пустой папки | Содержимое папки и намерение удалить его |
| Курсор мигает, ответа нет | Программа может ждать стандартный ввод | Какой ввод ей обещан и был ли он передан |
| Приглашение начинается с `>` | Скорее всего, не закрыта кавычка | Нажать Ctrl+C и набрать команду заново |

Ctrl+C прерывает текущую команду. Это нормальный способ остановить программу, которая ждёт ввод или работает не так, как ожидалось.

## 10. Перед следующим действием

Если решение не складывается, не перебирай команды наугад. Ответь на вопросы:

1. Из какой папки выполняется команда и как от неё вычисляется каждый путь?
2. Что можно узнать по именам, размерам и содержимому файлов до изменения или удаления?
3. Что именно сообщает каждый сигнал: стандартный вывод, поток ошибок и код возврата?

Затем придумай минимальную проверку одного предположения. Если после этого всё ещё непонятно, открой [`stuck_rus.md`](stuck_rus.md), собери команду, полный ответ терминала и свои наблюдения — и попроси соседа помочь разобраться. Просьба о помощи здесь часть работы, а не поражение.


## 11. Конвейер, printf и точный вывод

`|` передаёт вывод одной команды на ввод другой:

```bash
printf '7 3\n' | python3 src/calc.py
```

printf печатает ровно заданный текст; `\n` обозначает перенос строки. `printf '\n'` передаёт пустую строку, `printf ''` — конец ввода без строки. Для проверки невидимых символов:

```bash
printf '7 3\n' | python3 src/calc.py | cat -A
```

Если у результата есть завершающий перенос, cat -A показывает `$`. В приглашении оболочки возможны собственные служебные символы, поэтому положение курсора само по себе ненадёжно. Машинные проверки в tools сравнивают байты без изменений.

Каждая строка datasets/inputs.txt — отдельный запуск. Можно скопировать её в printf, сохраняя пробелы. Весь файл через `<` не заставляет программу обрабатывать много строк.

## 12. Аргументы shell-скрипта и пути с пробелами

В shell-скрипте `$1` — первый аргумент, `$2` — второй. Запись `${1:-значение}` выбирает значение по умолчанию, если аргумент не передали. Переменные задаются без пробелов вокруг `=`. Нейтральный пример:

```bash
input_path="${1:-source.txt}"
output_dir="${2:-output}"
python3 tool.py "$input_path" --dir "$output_dir"
```

Имена переменных выбирай осмысленные. Кавычки вокруг переменной сохраняют путь с пробелами одним аргументом. Перед удалением убедись, что рабочая папка именно та, которую создал генератор. Сначала просмотри совпадения маски через ls. Не удаляй корень проекта и папку исходников.

## 13. Наблюдение и воспроизведение

Команда `cp файл копия` позволяет сохранить данные для эксперимента. Старую ошибку воспроизводи в отдельной practice-копии или маленьком временном файле там же. В журнале укажи рабочую папку и точные команды. После объяснения не надо переносить намеренно сломанный код в сданную версию.
