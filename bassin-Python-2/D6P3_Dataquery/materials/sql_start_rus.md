# SQL: с чего начать

SQL — язык запросов к таблицам. Таблица здесь означает то же, что в обычной жизни: набор строк одного вида с одинаковыми полями. Одна строка — одно обращение в поддержку.

Главное отличие от Python: в запросе описывают, **что** хотите получить, а не **как** это обойти. Ты не пишешь цикл по строкам — ты говоришь «сгруппируй по каналу и посчитай среднее», а движок сам решает, в каком порядке читать данные.

## Четыре действия

Почти всю аналитику закрывают:

| Действие | Ключевые слова | Что делает |
|---|---|---|
| Выбрать строки | `SELECT … FROM … WHERE` | берёт нужные поля у строк, подходящих под условие |
| Сгруппировать | `GROUP BY` | собирает строки в группы по одинаковому значению поля |
| Посчитать по группе | `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` | считает по каждой группе отдельно |
| Соединить таблицы | `JOIN … ON` | подтягивает к строке данные из другой таблицы по общему полю |

Практическая разница ощутима: то, что на Python занимает 30 строк с вложенными словарями, в SQL занимает 4, и в них труднее ошибиться незаметно.

## Чего SQL не делает

Графики, нестандартные функции, разбор кривых форматов, любая логика сложнее группировки — всё это остаётся на Python. Рабочая схема на сегодня: SQL считает числа, Python готовит данные и рисует.

## SQLite и модуль sqlite3

Мы работаем с SQLite. Отдельный сервер не нужен, база живёт в файле или в памяти процесса, модуль `sqlite3` входит в стандартную библиотеку Python — ставить ничего не надо.

Подключение и курсор:

```python
import sqlite3
con = sqlite3.connect(":memory:")   # или "mydata.db", если нужен файл
cur = con.cursor()
```

Запрос выполняется через `cur.execute()`. Результат забирается либо циклом, либо `fetchone()`:

```python
for row in cur.execute("SELECT login, team FROM agents LIMIT 3"):
    print(row)

print(cur.execute("SELECT COUNT(*) FROM agents").fetchone())
```

Каждая строка приходит **кортежем**, поэтому в выводе видны скобки: `('ivan_p', 'первая линия')`. Одиночное число тоже кортеж, из одного элемента: `(19,)`.

## Обрати внимание

**Строка не равна числу.** Всё, что пришло из CSV, по умолчанию текст. `'10' < '9'` — правда, потому что сравниваются символы. Если поле нужно как число, приводи явно: `CAST(поле AS INTEGER)`.

**Пустая строка не равна отсутствию значения.** В базе есть отдельное состояние `NULL`, которое означает «значения нет». Пустая строка `''` — это значение, просто пустое. Условие `поле IS NULL` и условие `поле = ''` ловят разные строки. А при загрузке из CSV пустая ячейка обычно приезжает пустой строкой, а не `NULL`, — то есть какое из двух состояний окажется в базе, решает ваш загрузчик.

**Сравнение с `NULL` не возвращает ни правду, ни ложь.** Оно возвращает «неизвестно», и строка не проходит фильтр — ни при `= 'значение'`, ни при `!= 'значение'`. Отсюда классическая потеря строк, которую никто не замечает, потому что ошибки не возникает.
