## 1. Файл памяти

Текстовый файл, кодировка UTF-8. Одна строка — одна запись.

Строки разделяются переводом строки. Завершающий перевод строки в конце файла новой строки не образует: файл из трёх записей содержит три строки, а не четыре.

Одинаковых строк в файле нет. Файл читается целиком и корректен как текст: битых байтов, гигантских строк и прочих неожиданностей в нём не бывает. Твоя программа обязана пережить дефекты записей из раздела 6, а не поломки файловой системы.

## 2. Разбор записи

Запись разбирается разделением строки по символу `;`.

**Полей должно получиться ровно три.** Ни двух, ни четырёх: четыре поля — это `неверное число полей`, а не «лишнее отбросим».

**Каждое поле обрезается по краям**: пробелы и табуляции слева и справа отбрасываются до всех остальных проверок. Строка `09:12:05 ; SENSOR ; 21.4` разбирается так же, как `09:12:05;SENSOR;21.4`.

**Запись принята**, если выполнены все четыре условия:

1. полей ровно три;
2. имя модуля непустое и по формату раздела 5;
3. время в формате раздела 3;
4. значение — число раздела 4.

Не выполнено хотя бы одно — запись отбракована, причина берётся из раздела 6.

## 3. Время

Ровно восемь символов: `ЧЧ:ММ:СС`. По две цифры на каждую часть, разделитель — двоеточие.

Часы от `00` до `23`, минуты и секунды от `00` до `59`.

| Пример | Годится | Почему |
| --- | --- | --- |
| `09:12:05` · `23:59:59` | да | |
| `9:12:5` | нет | нет ведущих нулей |
| `24:00:00` | нет | часов больше 23 |
| `09:12` | нет | нет секунд |
| `09-12-05` | нет | не тот разделитель |

## 4. Значение

Десятичная запись: необязательный знак `+` или `-`, затем цифры, затем необязательно точка и хотя бы одна цифра после неё.

| Пример | Годится | Почему |
| --- | --- | --- |
| `21.4` · `-7` · `+0.5` · `0` · `-0.0` | да | |
| `21,4` | нет | разделитель — точка |
| `21.` | нет | после точки нужна цифра |
| `1e3` | нет | экспоненциальная запись не используется |
| `inf` · `nan` | нет | не числа этого формата |
| `--5` | нет | один знак |

`-0.0` — допустимое значение и в счёте ведёт себя как ноль.

## 5. Имя модуля

**Формат:** первая буква латинского алфавита, дальше латинские буквы, цифры и знак подчёркивания. Длина до шестнадцати символов. Регулярно: `[A-Za-z][A-Za-z0-9_]{0,15}`.

Регистр букв не ограничен: в файлах встречаются имена, различающиеся только регистром.

**Имя известно**, если полей ровно три и второе поле после обрезки непустое и по формату. Что не так со временем и значением, на известность имени не влияет: запись может быть отбракована, а имя из неё — известно.

Строка, где полей не три или имя пустое, **не добавляет имя в множество известных модулей**. То же имя может прийти из другой строки — тогда модуль известен.

Списка модулей заранее нет: множество известных имён целиком собирается из файла.

## 6. Классы порчи и приоритет

Проверки идут в этом порядке. Запись получает причину **первой сработавшей** проверки и попадает ровно в один счётчик, сколько бы дефектов в ней ни было.

Порядок совпадает с порядком разбора: пока строка не разбита на поля, про имя ничего сказать нельзя.

| № | Причина — печатается ровно так | Признак | Пример | Восстановимо |
| --- | --- | --- | --- | --- |
| 1 | `пустая строка` | После обрезки в строке ничего не осталось | `` | нет |
| 2 | `неверное число полей` | Полей не ровно три | `09:12:05;SENSOR` | нет |
| 3 | `пустое имя модуля` | Второе поле пусто | `09:12:05;;21.4` | нет |
| 4 | `неверное время` | Первое поле не по разделу 3 | `9:12:5;SENSOR;21.4` | да, см. раздел 9 |
| 5 | `пустое значение` | Третье поле пусто | `09:12:05;SENSOR;` | нет |
| 6 | `значение не число` | Третье поле не по разделу 4 | `09:12:05;SENSOR;21,4` | да, см. раздел 9 |

Имя, не подходящее под формат раздела 5, в файлах не встречается — отдельного класса для него нет.

**Пример на двух дефектах.** Строка `09:12:05;;21,4` — пустое имя и запятая в значении. Побеждает третий класс: `пустое имя модуля`. В счётчик `значение не число` эта строка не попадает.

## 7. Счётчики

**Разведочный вывод** (`--scan`), первая строка — три числа через пробел:

- сколько всего строк в файле;
- сколько из них разбирается ровно на три поля;
- сколько не разбирается.

Второе плюс третье всегда равно первому.

**Разбивка по модулям** (`--scan`, дальше первой строки) — строка на каждый модуль с известным именем и числом строк, где это имя встретилось. Считаются все такие строки, принята запись или нет. Строки без известного имени в разбивку не попадают, поэтому сумма по модулям может быть меньше второго числа.

Порядок: по убыванию количества, при равенстве — по возрастанию кодов символов имени.

**Причины отбраковки** — в поток ошибок, строка на причину: имя причины, пробел, количество. Порядок: по убыванию количества, при равенстве — в порядке приоритета из раздела 6. **Причины с нулевым количеством не печатаются.**

**Сходимость.** Принято плюс пропущено всегда равно числу строк в файле: пустые строки тоже попадают в пропущенные.

## 8. Отчёт

Печатается в стандартный вывод. Программа сама файлов не создаёт.

- Строка на модуль, три колонки: имя модуля, число принятых записей, среднее значение.
- Разделитель — пробел, вертикальная черта, пробел: `POWER | 2 | 13.000`.
- Порядок строк — по возрастанию кодов символов имени.
- Имя печатается ровно так, как оно встретилось в файле в первый раз.
- Если у модуля нет ни одной принятой записи, вместо среднего — дефис.
- Последняя строка: `ИТОГО | принято | пропущено`.
- Заголовков нет, пустых строк нет.
- Кодировка UTF-8, перевод строки `\n`, последняя строка заканчивается переводом строки.

**Среднее.** Считается по всем принятым значениям модуля без промежуточного округления и печатается с тремя знаками после точки. Нулевое среднее печатается как `0.000` — знака минус у нуля в отчёте не бывает.

Спора о том, куда округлять ровную половину, не возникает: в файлах данных нет значений, при которых среднее попадает ровно на половину третьего знака. Округляй так, как это делает обычное форматирование числа с тремя знаками.

## 9. Восстановление

Только для задания 7. В основной части ничего не восстанавливается: испорченная запись отбраковывается как есть.

### Что восстановимо

| Класс | Правило |
| --- | --- |
| `неверное время` | Каждая часть состоит из одной или двух ASCII-цифр. Однозначная часть дополняется слева нулём, двузначная остаётся как есть. После дополнения части должны попасть в допустимые пределы раздела 3 |
| `значение не число` | Если строка становится числом раздела 4 после замены всех запятых на точки — заменить |

Всё остальное не восстанавливается. `24:00:00` не чинится: часов больше 23 не бывает и после дополнения. `1e3` не чинится: это не запятая.

| Пример времени | Результат | Почему |
| --- | --- | --- |
| `9:2:5` | `09:02:05` | однозначные части дополнены |
| `9:12:05` | `09:12:05` | дополнена одна часть |
| `009:12:05` | не чинится | в части три цифры |
| `9:2:005` | не чинится | в части три цифры |
| `000:1:1` | не чинится | в части три цифры |
| `9:2:99` | не чинится | секунд больше 59 |

### Составные дефекты

В одной записи может быть несколько восстановимых дефектов: `9:12:5;SENSOR;21,4` — и время, и значение.

Алгоритм: **после каждого исправления запись проверяется заново.** Повторять, пока запись не станет корректной либо не обнаружится невосстановимый дефект. Во втором случае запись выбрасывается целиком, даже если часть дефектов уже исправлена.

Счётчик `восстановлено` считает **записи, а не исправленные поля**: строка выше даёт единицу, а не двойку.

### Что печатает `restore.py`

В стандартный вывод — исправленный журнал, по строке на запись, в исходном порядке файла:

- изначально корректные записи печатаются **как есть**, побайтово той же строкой, включая пробелы вокруг полей;
- восстановленные печатаются **в нормализованном виде**: три поля через `;` без пробелов вокруг — `09:02:05;SENSOR;21.4`;
- невосстановимые не печатаются вовсе.

В поток ошибок — ровно две строки:

```
восстановлено N
выброшено M
```

**Инвариант:** изначально корректные + восстановленные + выброшенные = всего строк в файле.

Исходный файл при этом не меняется.
