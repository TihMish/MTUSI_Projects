# Сравнение прототипов

## Критерии оценки (по 5-балльной шкале)

| Критерий | Описание |
|----------|----------|
| Соответствие пользовательскому сценарию | Насколько прототип позволяет выполнить основной сценарий |
| Понятность интерфейса | Насколько легко новому пользователю разобраться |
| Учёт ключевых состояний | Наличие состояний загрузки, ошибки, пустоты, успеха |
| Потенциал для расширения | Можно ли легко добавить новые функции |
| Общее впечатление | Субъективная оценка удобства и эстетики |

## Выбранный стартовый прототип

**Выбран:** Claude

**Аргументация:**
Прототип от Claude получил наивысшую оценку за счёт наилучшего баланса между соответствием сценарию, понятностью интерфейса и учётом состояний. Особенно важно, что этот прототип демонстрирует все ключевые состояния (загрузка, пустота, ошибка, успех), что делает его наиболее пригодным для демонстрации заказчику.

Интерфейс интуитивно понятен: пользователь сразу видит список комнат, фильтры расположены логично, а процесс бронирования занимает минимальное количество шагов. Также прототип легко расширять — структура позволяет добавлять новые функции, такие как уведомления или история бронирований.

Хотя остальные прототипы также имеют свои сильные стороны (например, GigaChat — высокая понятность), они уступают в полноте демонстрации состояний, что критично для MVP.
