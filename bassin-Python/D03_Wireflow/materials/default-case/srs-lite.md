# SRS-lite: MeetingFlow

## 1. Введение

### 1.1. Название продукта
MeetingFlow — сервис для бронирования переговорных комнат.

### 1.2. Цель продукта
Упростить и ускорить процесс бронирования переговорных комнат в кампусе «Школы 21».

### 1.3. Целевая аудитория
- **Пользователи (студенты и сотрудники):** бронируют комнаты для встреч и учёбы.
- **Администраторы:** управляют комнатами и бронированиями.

## 2. Роли и потребности

### Пользователь
- **Цель:** быстро найти и забронировать подходящую комнату.
- **Потребности:** видеть список комнат, проверять расписание, получать подтверждение бронирования.

### Администратор
- **Цель:** управлять ресурсами кампуса.
- **Потребности:** видеть все бронирования, управлять комнатами.

## 5. User Stories с критериями приёмки

### US-01: Просмотр списка комнат
**Как** пользователь, **я хочу** видеть список всех доступных переговорных комнат, **чтобы** выбрать подходящую для моей встречи.

**Критерии приёмки:**
- Главный экран содержит список комнат с названием, вместимостью и иконками оснащения.
- При нажатии на комнату открывается её страница.

### US-02: Фильтрация комнат
**Как** пользователь, **я хочу** фильтровать комнаты по вместимости и оснащению, **чтобы** быстро найти подходящий вариант.

**Критерии приёмки:**
- Доступны фильтры: «Количество участников», «Оснащение».
- Список обновляется после применения фильтров.

### US-03: Просмотр расписания комнаты
**Как** пользователь, **я хочу** видеть расписание выбранной комнаты на конкретную дату, **чтобы** понять, когда она свободна.

**Критерии приёмки:**
- На странице комнаты отображаются слоты с цветовой индикацией (свободные/занятые).
- При выборе свободного слота открывается форма бронирования.

### US-04: Бронирование слота
**Как** пользователь, **я хочу** забронировать свободный слот, **чтобы** гарантированно использовать комнату в нужное время.

**Критерии приёмки:**
- Форма бронирования содержит поля: «Название встречи», «Количество участников».
- При конфликте показывается сообщение и предлагается выбрать другой слот.

### US-05: Подтверждение бронирования
**Как** пользователь, **я хочу** видеть подтверждение моего бронирования, **чтобы** быть уверенным, что комната зарезервирована.

**Критерии приёмки:**
- Экран подтверждения содержит детали бронирования и кнопку возврата.

## 6. Edge Cases

| ID | Ситуация | Обработка |
|----|----------|-----------|
| EC-01 | Бронирование в прошлом | Сообщение: «Нельзя забронировать слот в прошлом». |
| EC-02 | Конфликт бронирования | Сообщение: «Слот занят. Выберите другой слот». |
| EC-03 | Превышение вместимости | Сообщение: «Количество участников превышает вместимость комнаты». |
| EC-04 | Пустое поле «Название встречи» | Сообщение: «Заполните название встречи». |
| EC-05 | Пустой список комнат | Сообщение: «Нет доступных комнат». |
| EC-06 | Нулевое количество участников | Сообщение: «Количество участников должно быть больше 0». |

## 7. Отложенные / отклонённые требования

| Требование | Статус | Причина |
|------------|--------|---------|
| Отмена бронирования | Отложено | Не критично для MVP |
| История бронирований | Отложено | Можно реализовать позже |
| Личный кабинет | Отложено | Для MVP достаточно базовой идентификации |
| Уведомления | Отложено | Улучшает опыт, но не критично для старта |
