# Обоснование MVP и бэклог доработок

## Состав MVP

| Функция | Почему критична | Какую гипотезу проверяет |
|---------|-----------------|--------------------------|
| Просмотр списка комнат | Пользователь не сможет ничего забронировать, если не увидит, какие комнаты доступны | Пользователям нужен удобный способ найти подходящую комнату |
| Просмотр расписания слотов | Нужно понимать, когда комната свободна | Пользователи готовы планировать заранее |
| Бронирование слота | Основная ценность продукта | Пользователи готовы бронировать комнаты онлайн |
| Подтверждение бронирования | Пользователь должен знать, что его действие выполнено | Пользователям нужна обратная связь об успехе операции |
| Сообщение об ошибке конфликта | Пользователь должен понимать, почему его бронирование не удалось | Пользователям нужны понятные объяснения отказов |

## Бэклог доработок

| Функция | Почему отложена | Приоритет |
|---------|-----------------|-----------|
| Отмена бронирования | Можно отложить, так как пользователь может просто не прийти (хотя это неудобно) | Высокий |
| История бронирований | Не влияет на возможность совершить первое бронирование | Средний |
| Личный кабинет | Для MVP достаточно базовой идентификации | Средний |
| Уведомления по email | Улучшает опыт, но не критична для первой проверки гипотезы | Низкий |
| Интеграция с календарём | Улучшает опыт, но требует дополнительной разработки | Низкий |
| Админ-панель управления комнатами | Для MVP достаточно загрузить комнаты вручную или через начальные данные | Высокий (для администраторов) |
| Фильтрация и поиск комнат | Улучшает опыт, но не критична для первого запуска | Средний |
| Система ролей и прав доступа | Для MVP достаточно одной роли пользователя | Низкий |
