Аналитика в компании не было давно.

Первого апреля на первой линии поддержки запустили базу знаний и бота: типовые вопросы теперь закрываются автоматически и до человека не доходят. Прошло полгода. Руководство хочет расширять автоматизацию на вторую линию* и просит подтверждение, что после апреля стало лучше.

\***Вторая линия (в продажах и клиентском сервисе)** — _служба, которая получает то, что первая закрыть не смогла. Здесь нужны люди, разбирающиеся в предмете: финансовые вопросы, техническая часть, работа с документами. Обращений меньше, времени на каждое уходит больше, сотрудники дороже._

### Задание 1. Первые запросы

**Сдать:** `ex01.py`

Работаем с `data/agents.csv`.

**❗ Если вы уверенный пользователь SQL, идите сразу в раздел "Что сделать" первого задания!**

Скопируйте в начало `ex01.py` этот код:

```python
import csv
import sqlite3
con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("""
CREATE TABLE agents (
    id TEXT,
    login TEXT,
    team TEXT,
    hired_at TEXT
)
""")
with open("data/agents.csv", encoding="utf-8") as f:
    rows = [
        (r["id"], r["login"], r["team"], r["hired_at"])
        for r in csv.DictReader(f)
    ]
cur.executemany("INSERT INTO agents VALUES (?, ?, ?, ?)", rows)
con.commit()
```

Запрос с несколькими строками можно вывести так:

```python
for row in cur.execute("SELECT login, team FROM agents LIMIT 3"):
    print(row)
```

**Запрос с одним результатом:**

```python
print(cur.execute("SELECT COUNT(*) FROM agents").fetchone())
```

**Что сделать**

Добавьте в `ex01.py` пять запросов. Перед каждым результатом напечатайте его номер и название.

1. Первые три сотрудника:

    ```sql
    SELECT login, team
    FROM agents
    LIMIT 3
    ```

2. Количество сотрудников:

    ```sql
    SELECT COUNT(*)
    FROM agents
    ```

3. Три сотрудника, нанятых раньше всех:

    ```sql
    SELECT login, hired_at
    FROM agents
    ORDER BY hired_at
    LIMIT 3
    ```

4. Количество сотрудников в каждой команде — напишите запрос самостоятельно. Подсказка: `GROUP BY`.

5. Сотрудники, нанятые в 2025 году — напишите запрос самостоятельно. Выведите логин и дату найма. Подсказка: `WHERE`.

    **Запуск:**

    ```bash
    python3 ex01.py
    ```

Скрипт должен без ошибок вывести результаты всех пяти запросов.

### Задание 2. Группировки и свои функции

**Сдать:** `ex02.py`

Работаем с тем же `data/agents.csv` и тем же загрузчиком, что в задании 1.

`GROUP BY` объединяет строки в группы, `HAVING` фильтрует уже готовые группы, а `WHERE` — строки до группировки.

Пример подсчёта по условию:

```sql
SELECT
    COUNT(CASE WHEN hired_at >= '2025-01-01' THEN 1 END) AS new_agents,
    COUNT(CASE WHEN hired_at < '2025-01-01' THEN 1 END) AS old_agents
FROM agents
```

**Свои функции SQLite**

Встроенный `lower()` SQLite по умолчанию работает только с ASCII:

```sql
SELECT lower('Первая Линия'), lower('ABC')
```

Результат:

```
('Первая Линия', 'abc')
```

Свою SQL-функцию можно зарегистрировать из Python:

```python
def double(x):
    return x * 2

con.create_function("double", 1, double)
```

Для своих агрегатных функций используется:

```python
con.create_aggregate(...)
```

**Что сделать**

В `ex02.py`:

1. Посчитай количество сотрудников в каждой команде и оставь только команды, где больше 5 сотрудников. Используй `GROUP BY` и `HAVING`.
2. Выведи количество сотрудников по годам найма.
3. Зарегистрируй SQL-функцию `unicode_lower`, которая приводит к нижнему регистру в том числе русский текст. Проверь: `SELECT unicode_lower('ПЕРВАЯ ЛИНИЯ')`. Результат должен быть: `('первая линия',)`.
4. Через `con.create_aggregate()` зарегистрируй агрегат `MEDIAN`. Посчитай им медианный год найма сотрудников. Встроенную `median()` SQLite не используй, даже если она доступна в вашей версии.
5. Отдельно посчитай медианный год найма средствами Python и напечатай оба результата рядом. Для `data/agents.csv` оба результата должны быть: `2024`.

Скрипт должен запускаться командой `python3 ex02.py` и выполняться без ошибок.

### Задание 4. Гипотезы

**Сдаётся:** `ex04.md`

Тезис, который нужно подтвердить: после апреля клиентский сервис стал лучше.

Работа устроена как список гипотез. Гипотеза — проверяемое утверждение, под которое пишется один запрос. Запрос даёт число, число требует интерпретации.

Два примера для формата:

| Гипотеза | Запрос дал | Вердикт | Интерпретация |
|----------|------------|---------|---------------|
| Обращений стало меньше — бот забрал часть потока | 2900 → 3100 | не подтверждена | поток не упал, а немного вырос; значит объём нагрузки не аргумент ни в одну сторону, и ссылаться на него нельзя |
| Люди стали быстрее получать первый ответ | медиана 55 → 18 мин | подтверждена | реакция ускорилась примерно втрое |

**Что сделать.** Объяви единицу счёта (это иногда называется "гранулярностью"): что ты считаешь одним наблюдением — обращение, диалог или человека. Варианты дают разные числа. Напиши, что выбрал и почему, одной строкой в начале файла.

Доведи таблицу до восьми гипотез — приведённые две не считаются, они образцы. Минимум две гипотезы должны остаться неподтверждёнными. По каждой приведи текст запроса: проверяющий будет их запускать.

### Задание 5. Три слайда

**Сдаётся:** `ex05.pdf`

Восемь гипотез из задания 4 — это черновая работа. Показывать её целиком никому не стоит: восемь строк таблицы руководство не читает. Нужно свернуть всё в три слайда, которые прочитает человек, не открывавший файл. И он вам не доверяет.

Делать можно в чем угодно, ограничение на SQL и Python касается анализа, а не оформления. На выходе — PDF, три страницы.

**Слайд 1. Вывод.**

**Слайд 2. Как получено.**
- срез — на каких строках считал;
- единица счёта — что взял за одно наблюдение;
- фильтры — что выбросил и почему;
- текст запроса, целиком;
- один график, построенный на Python, показывающий именно тот срез, на котором держится вывод.

**Слайд 3. Что не подтвердилось.**
- Хотел утверждать: …
- Проверка показала: …

## Приёмка проекта

**Приёмка индивидуальная.** Бонусной части в этом проекте нет.

Десять минут ты **рассказываешь** о своей работе по восьми пунктам из `materials/acceptance_rus.md`. Проверяющий слушает и отмечает, прозвучал ли ответ на каждый; уточняющие вопросы он задавать может, но время принадлежит тебе.

**Ты не знаешь, разбирался ли слушатель в этих данных.** Он мог дойти до задания 4, а мог остановиться на первом. Спрашивать нельзя, и он не скажет. Считай, что перед тобой руководитель, который умеет считать, но файл не открывал: объясняй с нуля, без снисходительности, и будь готовы углубиться, если попросят.

По одному из восьми пунктов есть отдельное требование: после объяснения слушатель должен своими словами пересказать механизм. Пересказал — пункт зачтён. Не смог — не зачтён, как бы хорошо ни звучал рассказ.

Проверяющий может увидеть чек-лист до того, как сдаст собственную работу. Это не нарушение и на оценку не влияет: зачёт строится на объяснениях, а не на памяти о списке вопросов.
