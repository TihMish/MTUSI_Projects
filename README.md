## Chapter I

### Рекомендации к проекту

Как учиться в «Школе 21»:

* На протяжении всего курса ты будешь самостоятельно добывать информацию. Пользуйся всеми доступными средствами поиска информации, к примеру, Google и GigaChat. Будь внимателен к источникам информации: проверяй, думай, анализируй, сравнивай.
* Взаимообучение (P2P, Peer-to-Peer) — это процесс, при котором учащиеся обмениваются знаниями и опытом, выступая одновременно в роли учителей и учеников. Этот подход позволяет учиться не только у преподавателя, но и друг у друга, что способствует более глубокому пониманию материала.
* Не стесняйся просить помощи: вокруг тебя такие же пиры, которые тоже проходят этот путь впервые. Не бойся откликаться на просьбы о помощи. Твой опыт ценен и полезен, смело делись им с другими участниками.
* Не списывай, а если пользуешься помощью — всегда разбирайся до конца, почему, как и зачем. Иначе твое обучение не будет иметь никакого смысла.
* Если ты на чем-то застрял и кажется, что уже все перепробовал, но по-прежнему непонятно, куда идти, — просто передохни! Проветрись, перезагрузи голову, и, возможно, в следующий раз тебе наконец придет нужное решение!
* Важен не только результат обучения, но и сам процесс. Нужно не просто решить задачу, а понять, КАК ее решить.

Как работать с проектом:

* Перед выполнением проект необходимо склонировать с GitLab в одноименный репозиторий.
* Все файлы с результатами необходимо создавать в папке `src` склонированного репозитория.
* После клонирования проекта необходимо создать ветку `develop` и вести разработку в ней. Пушить в GitLab также нужно ветку `develop`.
* В твоей директории не должно быть иных файлов, кроме тех, что обозначены в заданиях.
* Для работы с Git и терминалом используй инструкции из задания 1 — там пошагово описаны все команды: клонирование репозитория, создание ветки `develop`, добавление файлов и push.
* Для сравнения прототипов используй шаблон `template-comparison.md` из папки `materials` для задания 3.
* Для выполнения определенной части заданий рекомендуется использовать следующие ИИ-сервисы: GigaChat/YandexGPT/ChatGPT/Claude.
* Все диалоги с ИИ фиксируй в `ai-logs.md` в корне репозитория — это обязательный файл для сдачи проекта.

Дисклеймер:

* В этом проекте ты будешь активно применять генеративные ИИ-сервисы. Однако помни: твоя цель — научиться формулировать идеи, сравнивать варианты и принимать решения, а не просто копировать сгенерированный результат. Все выводы и аргументы должны быть осмыслены лично тобой.

## Chapter II

### Планирование и прототипирование цифрового продукта

Создание любого программного продукта начинается не с написания кода, а с чёткого понимания, зачем и для кого он создаётся. Первые этапы — планирование и прототипирование — помогают избежать дорогих ошибок, когда разработанный функционал оказывается невостребованным.

В этом проекте ты попробуешь себя в роли product-менеджера и дизайнера: выберешь реальную пользовательскую проблему, сформулируешь цель, опишешь целевую аудиторию и создашь первые low‑fi прототипы будущего веб-приложения. Особенность подхода — активное использование ИИ-инструментов как ассистентов, ускоряющих генерацию идей и визуализацию.

Цель проекта: освоить этапы планирования цифрового продукта и прототипирования с применением ИИ-инструментов, научиться сравнивать варианты решений и аргументированно выбирать стартовую версию продукта.

### Задание 1. Работа с Git и терминалом

Ты — основатель стартапа, который хочет запустить сервис для улучшения внутренних процессов в кампусе «Школы 21». Перед тем как приступить к формулировке идеи и созданию прототипов, тебе необходимо подготовить рабочее окружение: склонировать репозиторий проекта, создать ветку для разработки и научиться отправлять изменения в GitLab. Это поможет тебе сохранять свои результаты, делиться ими с участниками и проходить peer‑to‑peer проверки. В этом задании ты освоишь базовые команды терминала и Git, которые понадобятся во всех последующих проектах.

Твоя первая задача - настроить локальное окружение для работы над этим проектом: склонировать репозиторий, создать ветку `develop`, разместить в папке `src` тестовый файл и отправить изменения в удалённый репозиторий.

### Что нужно сделать

1. Открыть терминал (командную строку) и перейти в папку, где будут храниться учебные проекты (например, `~/school21`).
2. Склонировать репозиторий проекта с GitLab, используя команду `git clone <ссылка_на_репозиторий>`. Ссылку возьми на странице проекта (кнопка «Clone» → «Clone with SSH»).
3. Перейти в папку склонированного проекта: `cd <имя_папки>`.
4. Создать ветку `develop` и переключиться на неё: `git checkout -b develop`.
5. Внутри папки `src` создать текстовый файл `test.md` с произвольным содержимым (например, «Готов к работе»). Это можно сделать через терминал (`echo "Готов к работе" > src/test.md`) или через проводник/текстовый редактор.
6. Добавить файл в индекс и сделать коммит:
    ```bash
    git add src/[test.md](http://test.md)
    git commit -m "Добавлен тестовый файл для проверки Git"
    ```
7. Отправить изменения в удалённый репозиторий:
    ```bash
    git push origin develop
    ```
    Важно учесть:
    
    Без этой команды твои изменения останутся только на локальном компьютере. Остальные участники не смогут увидеть твою работу при проверке (P2P), а ты не сможешь сдать проект. `git push` — это единственный способ синхронизировать локальную ветку `develop` с удалённым репозиторием на GitLab. После каждого коммита выполняй push, чтобы твои наработки были доступны для проверки и защищены от потери.

8. Проверить результат в веб-интерфейсе GitLab: переключись на ветку `develop` и убедись, что в папке `src` появился файл `test.md`.

Перепроверь еще раз, чтобы двигаться к дальнейшим заданиям проекта:

* В локальном репозитории создана ветка `develop`, в папке `src` лежит файл `test.md`.
* В удалённом репозитории (GitLab) в ветке `develop` присутствует тот же файл.

Все дальнейшие результаты нужно будет добавлять в `src` и коммитить в ветку `develop`.

### Задание 2. Формулировка идеи и анализ ЦА

Подготовительная работа позади. Теперь ты приступаешь к основной работе над сервисом для улучшения внутренних процессов в кампусе «Школы 21». Тебе предстоит пройти путь от сырой идеи до первого прототипа, который можно будет показать потенциальным пользователям. Выбери один из предложенных сеттингов (кейсов) и детально проработай концепцию продукта.

Для этого выполни следующие шаги:

1. Ознакомься с вариантами кейсов:
   * Бронирование переговорных / учебных комнат.
   * Запись на консультации или менторские сессии.
   * Запись на кампусные мероприятия / воркшопы.
   * Бронирование оборудования или лабораторного инвентаря.
   * Запись в спортзал / тренировочную зону.
2. Выбери один кейс и кратко опиши свою идею: что будет делать сервис и почему он нужен.
3. Используй ИИ-ассистента (ChatGPT, GigaChat или другой) для уточнения и расширения идеи:
   * Сформулируй запрос: «Помоги уточнить цель и задачу продукта для сервиса [твоя идея]. Предложи 2–3 альтернативных формулировки и укажи, какая лучше подходит для MVP».
   * Попроси модель: «Опиши целевую аудиторию для [твоя идея]. Какие у неё явные и скрытые потребности?».
   * На основе полученных ответов создай итоговое описание продукта: название (рабочее), цель, ключевые потребности ЦА, один основной пользовательский сценарий (успешный путь).
4. Подготовь базовый промпт для генерации HTML-прототипа. Он должен содержать описание задачи, ключевые экраны и пользовательский сценарий. Этот промпт понадобится в следующем задании.
5. Сохрани результаты в файл `product-brief.md` (папка `src`). В файле должны быть:
   * Выбранный кейс и название продукта.
   * Цель и задача.
   * Описание целевой аудитории и её потребностей (явных и скрытых).
   * Пользовательский сценарий (текстовое описание).
   * Промпт для генерации прототипа.

### Задание 3. Генерация и сравнение прототипов

У тебя есть чёткое описание продукта и промпт. Теперь нужно быстро увидеть возможные варианты интерфейса и выбрать стартовый прототип для дальнейшей работы. Сгенерируй три разных low‑fi прототипа с помощью ИИ-сервисов, пройди по ним пользовательский сценарий и сравни по заданным критериям.

Порядок действий:

1. Возьми промпт из `product-brief.md`. Используй не менее трех разных ИИ-сервисов (например, ChatGPT, GigaChat, Claude). Для каждого сервиса получи один HTML-прототип. Если доступен только один сервис, сгенерируй три варианта, немного варьируя промпт (например, попроси «сделай акцент на мобильной версии», «упрощённый вариант с минимумом действий» и т. д.).
2. Сохрани полученные HTML-файлы в папку `src/prototypes`. Дай им осмысленные имена, например, с названием ИИ-инструмента (`gigachat.html` и т.д.).
3. Пройди основной пользовательский сценарий по каждому прототипу (как пользователь, выполняющий задачу). Обрати внимание на:
   * Логичность шагов.
   * Отображение состояний (пустые слоты, ошибки, подтверждения).
   * Удобство навигации.
4. Заполни шаблон сравнения прототипов (файл `template-comparison.md` доступен в корне проекта). Оцени каждый вариант по 5‑балльной шкале по следующим критериям:
   * Соответствие пользовательскому сценарию.
   * Понятность интерфейса (насколько легко разобраться новому пользователю).
   * Учёт ключевых состояний (загрузка, ошибка, конфликт доступности).
   * Потенциал для расширения (можно ли легко добавить новые функции).
   * Общее впечатление (субъективная оценка).
5. На основе оценок выбери один стартовый прототип. Кратко аргументируй свой выбор (2–3 абзаца) в том же файле сравнения.
6. Сохрани заполненный шаблон как `comparison.md` в папке `src`.

### Задание 4. Обоснование MVP и бэклог доработок

У тебя есть выбранный прототип. Нужно определить, без чего продукт может существовать на старте, а что стоит отложить. Обоснуй состав MVP и сформируй план доработок (backlog) на следующие итерации.

Выполни следующие шаги:

1. Проанализируй выбранный прототип и выдели минимальный набор функций, без которых продукт не сможет решать основную задачу пользователя. Это может быть, например, только просмотр доступных слотов и бронирование, без личных кабинетов, уведомлений и админ-панели.
2. С помощью ИИ проверь свою гипотезу:
   * Попроси модель: «Вот описание продукта и его прототип [краткое описание]. Предложи минимальный состав функций для MVP, чтобы проверить востребованность идеи. Объясни, почему остальные функции можно отложить».
   * Сравни результат ИИ со своим списком. Доработай итоговый перечень.
3. Опиши окончательный состав MVP в файле `mvp-rationale.md`. Для каждой включённой функции укажи:
   * Почему она критична для пользователя.
   * Какую гипотезу она помогает проверить.
4. Сформируй бэклог доработок — список функций, которые не вошли в MVP, но желательны в будущем. Оформи его в виде таблицы с колонками: «Функция», «Почему отложена», «Приоритет (высокий/средний/низкий)».
5. Сохрани файл `mvp-rationale.md` в папке `src`.

## Chapter III

### Результат проекта первого дня

В папке `src` твоего репозитория должны находиться:

* `product-brief.md` — описание продукта, ЦА и пользовательский сценарий.
* папка `prototypes` с тремя HTML-файлами (или ссылками на них).
* `comparison.md` — заполненный шаблон сравнения прототипов с аргументированным выбором.
* `mvp-rationale.md` — обоснование MVP и бэклог доработок.

Также ты должен разместить в корне репозитория файл ai-logs.md с сохранёнными диалогами с ИИ-сервисами — это поможет при обсуждении твоего проекта с пирами.

И убедись, что все изменения отправлены в удалённый репозиторий. Без `git push` пиры не увидят твою работу, а проверка (P2P) станет невозможной. После пуша зайди в GitLab → выбери ветку develop → убедись, что все файлы на месте и открываются корректно.
