# Начни здесь. День 01

Для работы нужны два пира, этот комплект и станция с Python 3.8+, Git, Bash и текстовым редактором. Все программы установлены заранее. Интернет, GitLab, платформа, SSH-ключи, конверты и участие стаффа в процессе не нужны. На двух станциях копии передаются через доступную папку обмена или накопитель; весь маршрут можно пройти и на одной станции в разных папках.

## Получение задания

1. Каждый пир распаковывает `Day01_participant.zip` в свою папку. Верхняя папка проекта называется `D1P1_Terminal`. Договоритесь, кто первым проверяет; потом поменяйтесь ролями. Ничья готовность не блокирует начало работы другого.
2. В терминале перейди в `D1P1_Terminal`. Выполни `python3 --version`, `git --version`, `bash --version`. Открой этот файл и README в редакторе. Если программы отсутствуют, станция не готова: это не ошибка решения и не повод снижать оценку. Комплект не включает установщики ОС, Python или Git.
3. Начни локальную историю одной командой, подставив своё имя или ник. Адрес может быть учебным, реальная почта не требуется:

```bash
python3 tools/day1.py start --name "Мой ник" --email "peer@example.invalid"
```

Команда создаёт исходный коммит, метку `day01-start` и ветку `develop`. Ничего не отправляется в сеть. Если репозиторий уже начат, повторно команду не выполняй.

4. Прочитай README и `check-list.yml`. Все шесть заданий доступны сразу. Выполняй 1, затем начни Git-сценарий 2 и продолжай его вместе с 3–5. Задание 6 необязательно. Журнал ошибок веди с первой попытки.
5. Если застрял, используй `materials/stuck_rus.md`: сообщение, эксперимент, справочник, сосед. Готовое решение с чужого экрана, телефона или от ИИ не является самостоятельным выполнением. Читать справочники можно без ограничений.

## Передача результата

Закоммить результаты в `develop`, сохрани слитую `feature/first-scripts`, убедись, что `git status` чист. Из корня проекта:

```bash
python3 tools/day1.py pack --out ../day01_submission
```

Каталог назначения должен быть новым. В нём два файла: `submission.bundle` и `submission.json`. Передай каталог пиру. Он подтверждает приём копированием к себе; это момент фиксации версии. Не заменяй переданные файлы. При техническом сбое до приёма создавай новый каталог; после приёма новые версии в эту проверку не принимаются.

Пир работает по `materials/peer_review_rus.md`, запуская инструменты из СВОЕЙ отдельно распакованной чистой копии Day01_participant.zip. Твоя копия инструментов не источник критериев. Практические изменения не коммитятся в сдаваемую версию.

## GitLab, если он есть на площадке

Следующие дни курса работают с сервером, поэтому там, где доступ выдан заранее, историю первого дня туда тоже отправляют:

```bash
git push origin develop feature/first-scripts day01-start
```

Это не заменяет сдачу. Зафиксированной версией остаётся переданный bundle: только он несёт контрольную сумму и момент заморозки. Порядок такой: сначала `pack`, потом при желании `push`.

Сервер не обязателен. Ни выдача, ни решение, ни проверка первого дня от него не зависят: без доступа и без сети день проходится целиком, а bundle остаётся единственным транспортом. Получение ключей и настройка доступа в учебное задание не входят и на оценку не влияют.
